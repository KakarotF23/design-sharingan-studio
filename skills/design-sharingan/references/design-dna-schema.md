# Design DNA Schema

Use this structure for `scan` and `assimilate` outputs. Be concrete enough to guide implementation, but describe principles rather than copying pixels blindly.

## 1. Product Intent
- Emotional tone
- Primary user action
- Information priority
- Density level: low / medium / high

## 2. Layout
- Screen regions and reading order
- Grid/alignment logic
- Safe-area and edge behavior
- Scroll behavior
- Above-the-fold priority

## 3. Spacing Rhythm
- Outer margins
- Section gaps
- Component padding
- Repeated spacing scale or inferred rhythm

## 4. Typography
- Display/body/meta hierarchy
- Weight and contrast relationships
- Line-height and wrapping behavior
- Numeric/data emphasis

## 5. Color & Surface Logic
- Background/surface relationship
- Accent usage
- Semantic colors
- Contrast requirements
- Borders, shadows, blur, elevation

## 6. Component Geometry
- Cards
- Buttons
- Inputs
- Chips/badges
- Avatars/illustrations
- Corner-radius logic

## 7. Navigation & Interaction
- Entry points
- Active states
- Back/close behavior
- Gestures
- Touch-target expectations

## 8. Motion Intent
- What deserves motion
- Motion intensity by state
- Enter/exit/state-change behavior
- Reduced-motion fallback

## 9. Product Translation
- KEEP
- REJECT
- ADAPT
- INVENT

## 10. Implementation Tokens
Summarize approved reusable tokens/components without inventing exact values when the reference does not justify them.
