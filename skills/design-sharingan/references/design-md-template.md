# DESIGN.md

## Design North Star
Describe the product's emotional target, audience, and what the interface must never feel like.

## Information Hierarchy
Define primary, secondary, and tertiary content across major surfaces.

## Layout & Spacing
Document safe areas, page margins, section rhythm, grid/alignment rules, and density expectations.

## Typography
Document text roles, hierarchy, weights, line-height behavior, numeric emphasis, and localization constraints.

## Color & Surfaces
Document background/surface levels, accent logic, semantic colors, borders/elevation, dark/light rules, and accessibility contrast.

## Components
Document reusable cards, buttons, navigation, chips, inputs, avatars/characters, sheets/modals, and state variants.

## Navigation
Document global navigation, feature entry points, back/close behavior, deep links, and when NOT to add a new tab.

## Motion
Define calm/default/high-impact motion levels, transition intent, reduced-motion behavior, and which interactions should remain static.

## Product States
For important features define: loading, empty, error, offline, locked, premium, permission-denied, and success states.

## Accessibility
Touch targets, text scaling, contrast, motion reduction, screen-reader naming, focus order, and localization constraints.

## Do / Don't
### Do
- Preserve product hierarchy and established patterns.
- Use references to extract principles.
- Keep new features visually native to the product.

### Don't
- Copy brand assets or proprietary copy from references.
- Add a new visual language for every feature.
- Sacrifice usability for visual similarity.
- Use motion everywhere merely because animation is available.
