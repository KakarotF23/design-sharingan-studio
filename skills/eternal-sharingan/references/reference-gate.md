# Reference Gate

Before a screenshot, website, moodboard, or competitor UI influences the product:

## KEEP
Principles that already fit the product genome.

## REJECT
Elements conflicting with UX, identity, accessibility, or screen-family logic.

## ADAPT
Useful ideas that require translation into existing tokens/components/patterns.

## INVENT
Product-specific needs the reference does not solve.

## Compatibility
- **NATIVE** — little translation needed.
- **ADAPTABLE** — useful principle; implementation must change.
- **CONFLICTING** — attractive but incompatible with current product logic.
- **IRRELEVANT** — does not solve the product problem.

Never rate compatibility by taste alone. State the product reason.
