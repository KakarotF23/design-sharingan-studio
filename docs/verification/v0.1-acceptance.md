This record distinguishes implementation verification from a product release decision. ## Acceptance flows

The deterministic browser acceptance test is [full-loop.spec.ts](../../tests/e2e/full-loop.spec.ts). It uses the explicitly configured fake agent provider only for E2E determinism, while exercising real project storage, approval, rendering, governance, and relation validation.

| Flow | Evidence asserted by the full loop |
| --- | --- |
| A — Project intake | A local renderable fixture is opened, canonical project metadata is saved, and the Studio route is resolved. |
| B — Reference → SCAN → EVOLVE | A PNG reference is stored, SCAN produces KEEP/REJECT/ADAPT/INVENT, one design approach is approved, and the target tree remains unchanged throughout V1. |
| C — Safe execution | A change proposal is made, explicit approval is required, and only the approved `package.json` mutation is recorded. |
| D — Mangekyō loop | A fresh browser render is persisted under `.design-sharingan/renders`, linked to round one, inspected, and escalated to `HUMAN_GATE`. |
| E — Design Genome | A Draft Genome is initialized, explicitly approved as authoritative, and linked to a Screen Registry. |
| F — Drift audit | A Drift Report and authenticated evidence catalog are saved with Genome and Registry identities/revisions. |
| G — Release Gate | The release POST returns `200`, persists a `RELEASE_GATE` session, and is projected in Reports with its evidence-backed result. |

The acceptance fixture intentionally expects `NOT_VERIFIED` for Flow G. It captures `/` only in the `default` state, so the required loading and error states have no authenticated fresh render. The gate reports `requiredStates: FAIL` and `freshRenders: FAIL`, plus unverified navigation, accessibility, and functional verification. No code or test weakens that result into a PASS.

## Policy-pressure evidence

Command:

```bash
pnpm acceptance
```

The test exercises the real core/engine boundaries and verifies six fail-closed laws:

1. Autonomous dependency installation returns `HUMAN_GATE`.
2. Autonomous navigation mutation returns `HUMAN_GATE`.
3. Autonomous file deletion returns `HUMAN_GATE`.
4. One inspected screen cannot produce a whole-app PASS.
5. Missing a fresh final render prevents a visual PASS.
6. Repeated drift remains a human decision and does not rewrite the Design Genome.
