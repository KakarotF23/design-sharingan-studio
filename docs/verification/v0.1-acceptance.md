## Acceptance flows

The deterministic browser acceptance test is [full-loop.spec.ts](../../tests/e2e/full-loop.spec.ts). It uses the explicitly configured fake agent provider only for E2E determinism, while exercising real project storage, approval, rendering, governance, and relation validation.

| Flow | Evidence asserted by the full loop |
| --- | --- |
| A — Reference Analysis | A local renderable fixture is opened, canonical project metadata is saved, a PNG reference is stored, and SCAN produces collectively nonempty KRAI (KEEP, REJECT, ADAPT, and INVENT). |
| B — Feature UX Evolution | A Feature Brief is evolved into bounded UX options, one design approach is explicitly approved, and the target tree remains unchanged throughout V1. |
| C — Safe Mode | A change proposal is explicitly approved; only the approved `package.json` mutation is recorded. The same Safe session then records RUNNING → CAPTURING → VERIFYING → COMPLETE with its own fresh render and visual evidence. Follow-up verification failures return to PROPOSING and require a new exact approval, as covered by Safe-store tests. |
| D — Mangekyō Loop | A fresh browser render is persisted, linked to round one, inspected, and escalated to HUMAN_GATE. After explicit Genome approval, a fresh second round consumes the authenticated Genome identity/version and reaches COMPLETE. |
| E — Design Genome | A Draft Genome keeps agent-derived rules `UNCONFIRMED`. The UI exposes only server-derived render-bound candidates, and explicit local-user approval promotes one exact selected rule into a signed authoritative Genome and evidence claim. |
| F — Drift Audit | A fresh post-approval authenticated `/#default` render is registered in the signed catalog before the audit. The saved Drift Report inspects that scope and ranks one `HIERARCHY` / `IMPORTANT` finding whose evidence ID resolves to the post-approval catalog entry and approved Genome rule. |
| G — Release Gate | Whole-product release is initially NOT_VERIFIED. A later explicitly selected default-state capture passes its complete bounded evidence and release checks. Earlier release checkpoints remain NOT_VERIFIED/unavailable in Reports instead of inheriting the new PASS. Overview projects actual saved evidence and offers Analyze Reference, Improve Screen and Audit Product. |

The initial whole-product case in Flow G intentionally expects `NOT_VERIFIED`. Its post-approval capture covers `/` only in the `default` state, so the required loading and error states have no authenticated fresh render. That gate reports `requiredStates: FAIL` and `freshRenders: FAIL`, plus unverified navigation, accessibility, and functional verification. The populated Flow F finding does not weaken these missing whole-product states into a PASS.

The final remediation adds a separate, explicitly selected scope after that negative case. It also tests finding-linked EVOLVE evidence, approved Genome propagation, ASSIMILATE and direction-only VERIFY, reload persistence, and SCAN live/busy/result-focus accessibility. The old Task 16 wording for Flow C was premature: Safe originally stopped at EDITING and borrowed later Mangekyō evidence. The revised Flow C assertion now requires the Safe session's own terminal state and render.

Polish debt requires an explicit signed local-user Design Decision, an unchanged approved Genome, recapture after the decision, and a complete release check set with no unresolved non-polish findings. Interactive workflows that the read-only browser has not exercised remain NOT_VERIFIED; still images cannot certify approved motion behavior.
