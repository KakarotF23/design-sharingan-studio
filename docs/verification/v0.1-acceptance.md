## Acceptance flows

The deterministic browser acceptance test is [full-loop.spec.ts](../../tests/e2e/full-loop.spec.ts). It uses the explicitly configured fake agent provider only for E2E determinism, while exercising real project storage, approval, rendering, governance, and relation validation.

| Flow | Evidence asserted by the full loop |
| --- | --- |
| A — Reference Analysis | A local renderable fixture is opened, canonical project metadata is saved, a PNG reference is stored, and SCAN produces collectively nonempty KRAI (KEEP, REJECT, ADAPT, and INVENT). |
| B — Feature UX Evolution | A Feature Brief is evolved into bounded UX options, one design approach is explicitly approved, and the target tree remains unchanged throughout V1. |
| C — Safe Mode | A change proposal is made and explicitly approved; only the approved `package.json` mutation is recorded; then the web project is run, a fresh render is captured, and visual verification is saved with the session evidence. |
| D — Mangekyō Loop | A fresh browser render is persisted under `.design-sharingan/renders`, linked to round one, inspected, and escalated to `HUMAN_GATE`. After Genome approval changes target-project knowledge, the same Human Gate path produces a fresh round-two render from the post-approval source revision. |
| E — Design Genome | A Draft Genome keeps agent-derived rules `UNCONFIRMED`. The UI exposes only server-derived render-bound candidates, and explicit local-user approval promotes one exact selected rule into a signed authoritative Genome and evidence claim. |
| F — Drift Audit | A fresh post-approval authenticated `/#default` render is registered in the signed catalog before the audit. The saved Drift Report inspects that scope and ranks one `HIERARCHY` / `IMPORTANT` finding whose evidence ID resolves to the post-approval catalog entry and approved Genome rule. |
| G — Release Gate | The release POST returns `200`, persists a `RELEASE_GATE` session, and is projected in Reports as `NOT_VERIFIED` with its evidence-backed result. |

The acceptance fixture intentionally expects `NOT_VERIFIED` for Flow G. Its post-approval capture covers `/` only in the `default` state, so the required loading and error states have no authenticated fresh render. The gate reports `requiredStates: FAIL` and `freshRenders: FAIL`, plus unverified navigation, accessibility, and functional verification. The populated Flow F finding does not weaken these missing whole-product states into a PASS.

## Policy-pressure evidence

```bash

```

The routine acceptance gate executes both the six policy-pressure checks and the two Vitest Playwright-configuration checks (eight assertions total). The configuration test remains ignored by Playwright browser discovery, while proving the E2E server is test-owned and fake-agent configured. The policy checks verify six fail-closed laws:

1. Autonomous dependency installation returns `HUMAN_GATE`.
2. Autonomous navigation mutation returns `HUMAN_GATE`.
3. Autonomous file deletion returns `HUMAN_GATE`.
4. One inspected screen cannot produce a whole-app PASS.
5. Missing a fresh final render prevents a visual PASS.
6. Repeated drift remains a human decision and does not rewrite the Design Genome.
